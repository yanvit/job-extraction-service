# Правила розмітки golden set

Golden set (`data/golden.jsonl`) — 10 вакансій, розмічених вручну за схемою `JobPosting` (`jobex/schema.py`).
Кожен рядок: `{"doc_id": "job_XX", "expected": {...}}`.

**Процес:** Claude запропонував розмітку за цими правилами. Людина (Vitalii) звірила кожне поле з текстом і виправила.
Перевірка відповідності схемі: `python -m jobex.golden check`. Зручний вигляд для звірки: `python -m jobex.golden review` → `data/golden_review.md`.

**Головний принцип:** розмічаємо те, що **написано в тексті**, за правилами нижче, а не те, що «мабуть, мали на увазі».
Якщо даних немає: `null`, `[]` або `unknown`.

## Вибір текстів
| Док | Чому в golden set |
|---|---|
| job_01 | українська, «Керівник» → head, `$$$$` замість вилки |
| job_03 | у заголовку «до $700», у сайдбарі `$500-700` |
| job_07 | багато навичок, англійська A1, «також розглядаємо з 2 роками» |
| job_10 | англійська; опис каже remote, сайдбар каже офіс/гібрид |
| job_12 | короткий Telegram-пост, вилка в ₴, «вільно» |
| job_15 | «50-70к» без валюти, компанія не названа |
| job_17 | «від 700грн/ год» (погодинно), «проект / штат» |
| job_20 | junior, `300–800$`, багато «буде плюсом» |
| job_24 | російською, обрізаний, майже порожній |
| job_29 | англійською, Rust/C++, «Kyiv region» |

## Правила по полях

**title**
- Назва позиції як у тексті, мовою оригіналу.
- Без зарплати, міста, емодзі, хештегів, назви компанії («... в JustSchool» → без «в JustSchool»).

**company**
- Назва роботодавця: бренд, проєкт або юр. назва.
- Опис на кшталт «Національна компанія по розробці кар'єрів» — це не назва → `null`.

**role_category**
- Найближча категорія.
- 1C/BAS/BAF → `erp_1c`.
- Sysadmin/cloud/інфраструктура → `devops`. Керівник технічного підрозділу отримує технічну категорію (керівник IT-інфраструктури → `devops`).
- Продаж курсів, консультант з продажу, pre-sales, ведучий вебінарів продажів → `sales`.
- Робота з кодом, що не є фронтендом/мобайлом (у т.ч. системне Rust/C++) → `backend`.

**seniority**
- Тільки за явним маркером: Intern/стажер → `intern`; Junior → `junior`; Middle → `middle`; Senior → `senior`; Lead/Team Lead → `lead`; Head/Керівник/Chief → `head`.
- Без маркера → `unknown`. Не вгадуємо ні за роками, ні за «без досвіду».

**work_format**
- `remote` (віддалено, робота на дому), `office`, `hybrid` (у т.ч. «1 день в офісі»).
- `flexible` — коли пропонують кілька форматів на вибір.
- Якщо опис роботодавця і метадані job-борду суперечать одне одному, віримо опису.
- Нічого не сказано → `unknown`.

**employment_type**
- Повна → `full_time`, неповна → `part_time`, проєктна → `freelance`.
- Кілька варіантів → перший згаданий.
- Самі години роботи («пн-пт 9-18») тип не визначають → `unknown`.

**locations**
- Де робота або звідки беруть кандидатів, англійською: міста (`Kyiv`, `Kraków`), країни (`Ukraine`, `Croatia`), регіони (`EU`, `Europe`, `Worldwide` для «Весь світ»).
- «Kyiv region» → `Kyiv`.
- Місто, згадане лише як орієнтир або клієнт, не беремо.

**salary**
- Лише числа: `$$$$`, «конкурентна», «обговорюється» → `null`.
- «до X» → `min=null, max=X`; «від X» → `min=X, max=null`.
- «к» = тисячі; пробіли в числах — роздільники тисяч.
- Валюта: $/у.е. → USD, грн/₴ → UAH. Український пост з голими числами → UAH.
- Період: «/год», «за годину» → `hour`; інакше `month`.
- Якщо є розмита і точна вилка (заголовок «до $700» і сайдбар «$500-700»), беремо точнішу.

**experience_years_min**
- Основна вимога до ролі в роках: «від 3 років», «5+ years». «Від 6 міс» → 0.5.
- «Без досвіду» → 0. Не вказано → `null`.
- Додатковий варіант («також розглядаємо з 2 роками») не змінює основну вимогу.

**skills**
- Технології, інструменти, платформи, мови програмування, фреймворки, БД, які кандидат має знати або використовувати: вимоги, стек ролі, «буде плюсом».
- `required: true` для вимог і стеку; `false` для «буде плюсом» / nice to have.
- Не беремо: soft skills, людські мови, освіту, стандарти й сертифікації (ISO, PCI DSS), загальні поняття («distributed systems», «API» без конкретики).

**languages**
- Людські мови з рівнем CEFR, ISO-код: `en`, `uk`, `ru`...
- Мапінг рівнів:
	- Beginner / Початківець → A1;
	- Pre-Intermediate → A2;
	- Intermediate / Середній → B1;
	- Upper-Intermediate / Вище середнього → B2;
	- Advanced → C1;
	- Fluent / Вільний / вільно → C2;
	- Носій мови / native → `native`;
	- мова без рівня → `unknown`.
- Рівень з метаданих job-борду (сайдбар Djinni) рахується.

**posting_language**
- Мова основного опису (UI job-борду ігноруємо): `uk`, `en`, `ru`.
- `mixed` — лише якщо сам опис суттєво змішує мови.

## Відомі неоднозначності (свідомі рішення)
- **job_10, локації:** сайдбар «Країни Європи та Україна», в описі «Kraków is a plus», офіс у Хорватії. Беремо всі чотири: `Europe`, `Ukraine`, `Kraków`, `Croatia`.
- **job_17, employment_type:** «remote / проект / штат». Перший тип зайнятості — «проект» → `freelance`.
- **job_01, skills:** стек з розділу «Про роль» (Microsoft, VMware, Cisco...) рахуємо як required; стандарти ISO/PCI DSS не беремо.
